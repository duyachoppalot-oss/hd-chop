# HD Chop mobile

Expo SDK 58 + Expo Router (TypeScript). Routes live in `src/app/`:

| Route | Screen |
|---|---|
| `/` | Pick year (`/v1/years`) |
| `/models/[year]` | Pick model, grouped by platform; models with no fitment greyed out |
| `/search` | Selected bike + search box + quick-pick words |
| `/results?q=` | `/v1/search`: concept chips (up to 3), part cards, ±10-year toggle (`all=1`), trigram fallback |
| `/part/[oem]` | `/v1/part/:oem`: newest number, replaces, fits per model split by conditions |

Shared code: `src/lib` (theme, API client, bike context, formatting), `src/components`.
The selected bike lives in memory only (saved garage is Phase 4).

Run:

```
npm --prefix apps/mobile install
npm --prefix apps/mobile start        # QR code for Expo Go on a phone
npm --prefix apps/mobile run web      # browser (Claude preview: "mobile-web" in .claude/launch.json)
npm --prefix apps/mobile run typecheck
```

The app calls the deployed API (https://hdchop.5.161.100.126.nip.io). Point it elsewhere with
`EXPO_PUBLIC_API_URL`, e.g. `EXPO_PUBLIC_API_URL=http://<mac-lan-ip>:3001 npm --prefix apps/mobile start`
against `npm --prefix apps/api run dev`.

### App key

Every `/v1/*` call sends `X-App-Key` from `EXPO_PUBLIC_APP_KEY` (`src/lib/api.ts`); the API answers 401 without a
key it knows (`HDCHOP_APP_KEYS` in `~/hd-chop/api.env`, see apps/api/README.md).

- Simulator, Expo Go, web (`npm start` / `run web` / `npx expo run:ios`): Expo reads `apps/mobile/.env`, one line
  `EXPO_PUBLIC_APP_KEY=<key>` (same value as `HDCHOP_APP_KEYS` in the repo-root `.env`; both gitignored). Restart
  `expo start` after changing it (`-c` to clear the cache).
- EAS builds: not in `eas.json` (that file is committed). Each profile names an EAS environment (`production`;
  `preview` for internal builds); set the key once per environment:
  `npx eas-cli@latest env:create --environment production --name EXPO_PUBLIC_APP_KEY --value <key> --visibility sensitive`
  (again with `--environment preview`).
- Web dev: the API allows CORS only from http://localhost:8081 and :8083, and only when not in production, so Expo web
  works against `npm --prefix apps/api run dev`, not against the deployed API.

The key ships inside the app binary, so anyone can pull it out: it only stops casual scraping. The real protection is
the nginx rate limit (30 requests/min per IP, docs/FIX_PLAN.md A2) and server-side paid gating (C2).

## App icon and splash

`assets/*.png` are generated by `python3 apps/mobile/scripts/make-icons.py` (Pillow + the Oswald font in
`node_modules`): black and gold "HD / CHOP" counter-sign lettering, no H-D logos. `icon.png` is opaque 1024 px
(App Store rejects alpha). The native splash (`expo-splash-screen`) shows the lockup on `#0B0A08` and stays up until
the fonts load (`src/app/_layout.tsx`).

## TestFlight (EAS Build)

Config: `app.json` (bundle ID, splash, `ITSAppUsesNonExemptEncryption: false` — the app only uses HTTPS, so no export
compliance question per build) and `eas.json` (profiles `simulator`, `preview`, `production`; build numbers managed
remotely by EAS; `EXPO_PUBLIC_API_URL` baked in per profile). Placeholders to replace before the first build:

| Where | Placeholder | Replace with |
|---|---|---|
| `app.json` `ios.bundleIdentifier`, `android.package` | `com.yourname.hdchop` | your reverse-domain ID, permanent once on the App Store |
| `eas.json` `submit.production.ios.appleId` | `YOUR_APPLE_ID_EMAIL` | Apple ID email of the developer account |
| `eas.json` `submit.production.ios.appleTeamId` | `YOUR_TEAM_ID` | 10-character Team ID (developer.apple.com → Membership) |
| `eas.json` `submit.production.ios.ascAppId` | `YOUR_APP_STORE_CONNECT_APP_ID` | numeric Apple ID of the app record in App Store Connect |

Steps (run from `apps/mobile`):

```
npx eas-cli@latest login                 # Expo account (free)
npx eas-cli@latest init                  # creates the EAS project, writes extra.eas.projectId into app.json
npx eas-cli@latest build -p ios --profile production    # signs with your Apple account (asks to log in / create certs)
npx eas-cli@latest submit -p ios --profile production   # uploads to App Store Connect -> TestFlight
```

`--profile simulator` builds an `.app` for the iOS Simulator without an Apple account.
Before the App Store (not needed for internal TestFlight): a real API domain instead of nip.io, a privacy policy URL,
screenshots, and the legal review noted in docs/DATA_RIGHTS.md (data source terms + the "HD" name/trademark).
